# Code of Conduct

## Our commitment

PR HUB is maintained by and for people working together — engineers,
the PR Coordinator, and anyone else who contributes a rule, a Knowledge
Base entry, a bug report, or a review. We commit to making participation in
this project a respectful, harassment-free experience for everyone,
regardless of role, seniority, background, or how technical their
contribution is.

A non-technical contribution — validating a Training Mode report,
proposing a rule correction from real-world PR judgment — is exactly as
valuable as a code contribution, and is held to the same standard of
respectful treatment.

## Expected behavior

- Be respectful and constructive in issues, pull requests, and reviews.
- Assume good faith. If a rule proposal or a piece of feedback seems wrong,
  ask why before dismissing it — the person closest to the real PR work is
  often right about something the Rule Engine got wrong.
- Give feedback on the work, not the person. "This rule's condition is too
  broad" is useful; "this is a sloppy PR" is not.
- Accept correction gracefully, and offer it the same way. This project's
  own Training Mode exists because the system is expected to be wrong
  sometimes — the same grace applies to people.
- Respect that Spanish and English both appear in this repository's
  history and documentation; don't treat either as more "correct."

## Unacceptable behavior

- Harassment, insults, or personal attacks, in any project space (issues,
  PRs, commit messages, code review comments)
- Dismissing a contribution because of who made it rather than its content
- Publishing others' private information without consent
- Any conduct that would reasonably be considered inappropriate in a
  professional setting

## Scope

This Code of Conduct applies within all project spaces (this repository's
issues, pull requests, and discussions) and in any other setting where
someone is representing the PR HUB project.

## Reporting

If you experience or witness unacceptable behavior, report it to the
project maintainer(s) listed in [`SECURITY.md`](SECURITY.md). Reports will
be handled with discretion. As this is an internal project, reports may
also be escalated through Stellantis Chile's standard internal channels
where appropriate.

## Enforcement

Maintainers are responsible for clarifying and enforcing these standards,
and may remove, edit, or reject comments, commits, and other contributions
that don't align with this Code of Conduct, and may temporarily or
permanently restrict a contributor's participation for behavior they deem
inappropriate, threatening, or harmful.
